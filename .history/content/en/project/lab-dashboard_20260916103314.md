### Status
**Not implemented**

### Problem

Laboratory records are currently maintained in physical logbooks and disconnected spreadsheets updated by multiple individuals. Searching for a specific record requires manually flipping through pages. Cross-referencing data across dates, analysts, or services is not feasible during daily operations. There is no single location to view current laboratory activity at any given moment.

### What was built

An interactive Streamlit application serving as both a structured digital logbook and an operational KPI dashboard, with the potential to expand into a full operational LIMS. Staff enter records via an intuitive, comprehensive form interface; the application stores, organizes, and displays data, enabling immediate searching, filtering, and comparison without unnecessary page reloads.

### Technology

- **Python**: Backend data logic and application structure.
- **Streamlit**: Interactive web interface for data entry and visualization.
- **Pandas**: Structuring, filtering, and KPI aggregation.

### How it works

1. Laboratory staff enter daily records using a structured form on the web interface (service type, analyst, result, date, observations).
2. Entries are stored and indexed so that any record can be retrieved by date, analyst, or service without reviewing physical pages.
3. The dashboard layer aggregates entries into operational KPIs: daily volume by service, QC pass rates, and workload distribution among analysts.

### Outcome

- **Metric**: Fully digital logbook system — eliminates manual logging by multiple users and streamlines record searching and cross-referencing.
- **Impact**: The laboratory would no longer need to maintain parallel physical and digital records. Data entered once becomes immediately queryable. Decision-making based on operational trends becomes possible without the need for manual report preparation. ### Evidence
